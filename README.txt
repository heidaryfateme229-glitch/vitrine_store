VITRIN STORE — نسخه ۲ (فرانت‌اند + بک‌اند + PostgreSQL)
=======================================================

این پروژه یک فروشگاه نمونه فارسی و راست‌چین است. محصولات اولیه، قیمت‌ها و توضیحات آن‌ها داده‌های نمایشی هستند و پیش از استفاده تجاری باید با اطلاعات واقعی مالک فروشگاه جایگزین شوند.

قابلیت‌ها
---------
- نمایش محصولات با تصویرهای SVG محلی؛ بنابراین تصاویر نمونه به سرویس خارجی وابسته نیستند.
- جست‌وجو و فیلتر دسته‌بندی.
- صفحه جزئیات محصول، مشخصات، قیمت، موجودی و میانگین امتیاز.
- ثبت‌نام و ورود مشتری با گذرواژه هش‌شده و توکن نشست.
- سبد خرید ماندگار در مرورگر و ثبت سفارش در PostgreSQL.
- پیگیری سفارش‌های حساب مشتری.
- ثبت نظر و امتیاز و تصویر مشتری؛ تصویر نظر در PostgreSQL ذخیره می‌شود.
- نشان «خرید تأییدشده» فقط برای کاربری نمایش داده می‌شود که سفارش محصول را با وضعیت تحویل‌شده داشته باشد.
- پنل مدیر برای افزودن/پنهان‌کردن محصول، مشاهده سفارش‌ها و تغییر وضعیت آن‌ها.
- رابط واکنش‌گرا برای موبایل و دسکتاپ.

پیش‌نیازهای اجرای محلی
----------------------
1) Node.js نسخه 20 یا جدیدتر.
2) PostgreSQL نسخه 14 یا جدیدتر.
3) یک پایگاه داده با نام vitrin.

راه‌اندازی در ویندوز و VS Code
------------------------------
1) پوشه demo-store-ui را در VS Code باز کن.
2) PostgreSQL را نصب کن و در pgAdmin یک Database با نام vitrin بساز.
3) فایل backend/.env.example را به backend/.env کپی کن.
4) در backend/.env مقدار DATABASE_URL را با رمز واقعی PostgreSQL خودت تنظیم کن. JWT_SECRET را نیز با یک رشته تصادفی طولانی عوض کن. برای ADMIN_EMAIL و ADMIN_PASSWORD ایمیل و رمز اختصاصی مدیر را تعیین کن.
5) در VS Code از منوی Terminal گزینه New Terminal را بزن.
6) این دستورها را اجرا کن:

   cd backend
   npm install
   npm run dev

7) در مرورگر http://localhost:4000 را باز کن.
8) برای بررسی اتصال API و پایگاه داده، http://localhost:4000/api/health را باز کن؛ پاسخ سالم باید status=ok و database=connected داشته باشد.

نکته: دیگر از Live Server برای این نسخه استفاده نکن؛ Express هم API را اجرا می‌کند و هم فایل‌های سایت را ارائه می‌دهد. اجرای index.html به‌صورت مستقیم یا با Live Server باعث می‌شود مسیرهای /api کار نکنند.

ساخت حساب مدیر
--------------
در backend/.env این سه مقدار را تنظیم کن:
ADMIN_EMAIL=ایمیل مدیر
ADMIN_PASSWORD=گذرواژه قوی و منحصربه‌فرد
JWT_SECRET=رشته تصادفی طولانی و محرمانه

هنگام شروع سرور، حساب مدیر ساخته یا به‌روزرسانی می‌شود. هرگز فایل .env را در GitHub قرار نده و رمزها را برای کسی ارسال نکن.

انتشار در Render
----------------
راهنمای کامل در فایل DEPLOY-RENDER.md است. خلاصه:
- پروژه را در یک مخزن خصوصی یا عمومی GitHub بارگذاری کن.
- در Render یک PostgreSQL بساز و Internal Database URL را بردار.
- از روی render.yaml یک Web Service بساز و متغیرهای DATABASE_URL، ADMIN_EMAIL و ADMIN_PASSWORD را وارد کن.
- JWT_SECRET به‌صورت خودکار تولید می‌شود.
- پس از Deploy، /api/health را بررسی کن.

محدودیت‌ها و موارد لازم پیش از فروش واقعی
-----------------------------------------
- پرداخت بانکی/درگاه پرداخت متصل نشده؛ سفارش‌ها فعلاً با پرداخت در محل ثبت می‌شوند.
- ایمیل و پیامک تأیید سفارش، بازیابی رمز و اطلاع‌رسانی خودکار فعال نیست.
- محصولات، موجودی، قیمت‌ها، توضیحات و تصاویر فعلی نمونه‌اند.
- سیاست واقعی ارسال، مرجوعی، حریم خصوصی، شرایط استفاده و اطلاعات تماس باید توسط مالک فروشگاه تکمیل و تأیید شوند.
- برای فروش واقعی، قوانین تجارت الکترونیک محل فعالیت، مالیات، حریم خصوصی و الزامات درگاه پرداخت باید بررسی شوند.
- تصاویر نظرات در PostgreSQL ذخیره می‌شوند؛ محدودیت هر تصویر ۷۰۰ کیلوبایت است. برای مقیاس بزرگ‌تر بهتر است فضای ذخیره‌سازی اختصاصی تصویر/CDN اضافه شود.
- Rate limit و اعتبارسنجی پایه فعال‌اند، اما پیش از پذیرش ترافیک عمومی گسترده، بازبینی امنیتی مستقل و تست نفوذ مجاز لازم است.
- حساب مدیر فقط از طریق متغیرهای محیطی سرور ایجاد می‌شود؛ هیچ رمز مدیر پیش‌فرضی داخل کد وجود ندارد.
